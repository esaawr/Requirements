# BSA 02 — Модели «As Is» / «To Be» и контекстные диаграммы

Учебный проект по дисциплине «Бизнес-системный анализ» (BSA).  
В рамках проекта выполнены задания по анализу текущего состояния системы (**as is**), проектированию будущего состояния (**to be**), построению контекстных диаграмм и описанию потоков данных для двух предметных областей: **сеть барбершопов (BRB)** и **служба доставки заказов (DEL)**.

---


> **Примечание:** В рамках проекта BSA 02 основное внимание уделено моделям as is / to be, контекстным диаграммам и потокам данных. Задания ex00–ex04 выполняются для обеих задач (барбершоп и доставка).

---

## 📌 Выполненные задания

### Exercise 00 — Роли и их действия as is
- Создана таблица ролей и их действий в текущем состоянии (as is) для каждой задачи.
- Из описания задачи выписаны все предполагаемые роли стейкхолдеров и их действия.
- Указаны проблемы, возникающие перед ролями в текущем состоянии.
- Актуализирован каталог стейкхолдеров из предыдущего проекта.

**Файлы:**
- `ex00_BRB_asis.xlsx`
- `ex00_DEL_asis.xlsx`

**Пример (DEL, фрагмент):**

| Идентификатор | Роль | Действие | as is (по телефону) | as is (очно) | Проблемы |
|---|---|---|---|---|---|
| st00200 | Курьер | Просмотр доступных заказов | + | - | Не видит заказы оперативно |
| st00200 | Курьер | Бронирование заказа | + | - | Путаница, двойное бронирование |
| st00200 | Курьер | Получение заказа в точке выдачи | - | + | Нет подтверждения |
| st00200 | Курьер | Просмотр оплаты | - | - | Неясно, сколько заработал |

### Exercise 01 — Создание контекстной диаграммы
- Разработана контекстная диаграмма для каждой задачи.
- На диаграмме указаны:
  - Стейкхолдеры и их действия, направленные в систему или получаемые из системы.
  - Сторонние системы и потоки данных, которыми система с ними взаимодействует.
- Определены границы системы.

**Файлы:**
- `ex01_BRB_context.*` (изображение)
- `ex01_DEL_context.*` (изображение)

**Пример контекстной диаграммы (DEL):**

### Exercise 02 — Разрешение проблем стейкхолдеров (to be)
- Дополнена таблица as is действиями пользователей системы to be.
- Для каждой проблемы указано решение, которое предоставляет система.
- Уточнены диаграмма и исходная таблица.

**Файлы:**
- `ex02_BRB_tobe.xlsx`
- `ex02_DEL_tobe.xlsx`

**Пример (DEL, фрагмент):**

| Идентификатор | Роль | Действие | as is | Проблемы | to be (в системе) | Решение проблемы |
|---|---|---|---|---|---|---|
| st00200 | Курьер | Просмотр доступных заказов | + | Не видит заказы оперативно | + | Видит заказы сразу |
| st00200 | Курьер | Бронирование заказа | + | Путаница, двойное бронирование | + | Бронировать заказ может только один человек без путаницы |
| st00200 | Курьер | Просмотр оплаты | - | Неясно, сколько заработал | + | Отслеживание оплаты за кол-во заказов |

### Exercise 03 — Проверка входных/выходных потоков данных
- Построена таблица входных/выходных потоков данных на основе контекстной диаграммы.
- Указаны внешние сущности, их тип, входящие и исходящие потоки.

1. Освоить методы анализа текущего состояния системы (as is).

4. Научиться описывать входные и выходные потоки данных.
5. Дополнять глоссарий и каталог стейкхолдеров по мере анализа.
